# parkinsons_desease_progression_problem
# Прогнозирование прогрессирования болезни Паркинсона на основе данных белков и пептидов

## Автор: Ангелова Анастасия

## Постановка задачи

Цель проекта — разработать модель для прогнозирования прогрессирования болезни Паркинсона, измеряемого по шкале **MDS-UPDRS**, с использованием данных по уровням белков и пептидов, полученных методом масс-спектрометрии.

Прогнозирование этих показателей важно для:

- понимания динамики заболевания,
- ранней диагностики,
- оптимизации лечебных вмешательств.

---

## Формат входных и выходных данных

### Входные данные:

- `train_peptides.csv`: данные масс-спектрометрии на уровне пептидов.
  - Поля: `visit_id`, `visit_month`, `patient_id`, `UniProt`, `Peptide`, `PeptideAbundance` 

  В данной имплементации эти данные не используются, так как не показали эффективности при отборе признаков

- `train_proteins.csv`: агрегированные данные по белкам.
  - Поля: `visit_id`, `visit_month`, `patient_id`, `UniProt`, `NPX`
- `train_clinical_data.csv` и `supplemental_clinical_data.csv`: клинические данные.
  - Содержат оценки по шкале **MDS-UPDRS (части 1–4)** и информацию о приёме медикаментов.

### Выходные данные:

Таблица с предсказанными значениями шкалы MDS-UPDRS для каждого визита пациента.  
Предсказания делаются для:

- текущего визита,
- горизонтов в **6, 12 и 24 месяца** вперёд.

Каждая запись включает:

- идентификатор пациента (`patient_id`),
- месяц визита (`visit_month`),
- предсказанное значение клинической оценки (`updrs_1–4`).

---

## Метрики

Для оценки качества модели используется **симметричная средняя абсолютная процентная ошибка (SMAPE)**  
С модификацией: `+1` в знаменателе, чтобы корректно обрабатывать случаи, когда прогноз и факт равны нулю.

SMAPE подходит, так как:

- учитывает относительные ошибки,
- адекватен при разных масштабах значений.

---

## Валидация

Для оценки качества модели используется подход, исключающий утечку данных между обучающей и тестовой выборками.  
Разделение данных проводится **по пациентам**, чтобы не использовать данные одного и того же пациента в обучении и тестировании одновременно.

## Данные

Проект основан на **реальных данных AMP-PD**, собранных в рамках **Accelerating Medicines Partnership Parkinson’s Disease (AMP-PD Knowledge Platform)**.  
Источник: [Kaggle competition page](https://www.kaggle.com/competitions/amp-parkinsons-disease-progression-prediction/data)

- дополнительные данные о повторных визитах позволяют учитывать **динамику заболевания**.

## Моделирование

### Бейзлайн

Модель линейной регрессии с единственным признаком — `visit_month`.

- Отдельная модель для каждого из `updrs_1`, `updrs_2`, `updrs_3`, `updrs_4`
- Минимальный базовый уровень прогноза
- Источник: [baseline kernel](https://www.kaggle.com/code/renataghisloti/simple-linearregression-updated-56-6-smape)


### Основная модель

Ансамблевое решение:

#### LightGBM
- Прогнозы постобрабатываются для минимизации SMAPE
- Признаки:
  - месяц визита, горизонт прогноза,
  - наличие данных крови,
  - клинические признаки,
  - количество предыдущих визитов

#### Нейронная сеть (PyTorch)
- Архитектура: несколько скрытых слоёв, Leaky ReLU
- Оптимизатор: Adam
- Scheduler: косинусный

#### Bagging
- Повышает стабильность и точность предсказаний

Обсуждение решения: [форум Kaggle](https://www.kaggle.com/competitions/amp-parkinsons-disease-progression-prediction/discussion/411505)

## Train

Этот проект использует **Hydra** для гибкого конфигурирования, а запуск команд осуществляется через `python -m`.

Обучение модели включает несколько этапов:
- загрузка данных (можно из локальных файлов или через DVC),
- предварительная обработка,
- обучение модели (`LightGBM` или `PyTorch Lightning`),
- сохранение модели (в формате ONNX),
- логгирование с помощью MLflow.

Все этапы можно запускать централизованно через конфигурационные файлы в `configs/`, где указывается стратегия (`train_lightning`, `train_lgbm` и т.д.), а также пути к данным, параметры моделей и логгирования.

> ***ВАЖНО!*** В качестве dvc используется gdrive, для работы с dvc необходимо положить `credentials.json` в корень проекта. Данный файл можно взять либо написав мне в tg: @nuangelova, либо скачав с [dropmefiles](https://dropmefiles.com/35AXN), пароль: re6tlu

### Базовые команды запуска


#### Обучение модели нейронной сети:

```bash
python -m parkinsons_desease_progression_prediction.commands task=train_lightning
``` 

#### Обучение модели LightGBM:

```bash
python -m parkinsons_desease_progression_prediction.commands task=train_lgbm
```

> Оба варианта **включают загрузку данных и предварительную обработку**, если в конфигурации установлен флаг `use_preprocessing: True`, в противном случае будет ожидаться, что данные были предобработаны и лежат по нужным путям.

---

### Дополнительные команды (если нужен поэтапный запуск, данные этапы уже включены в обучение, поэтому можно пропустить)

#### Загрузка данных

```bash
python -m parkinsons_desease_progression_prediction.commands task=load_data task.mode=all
```

* `mode=train|inference|all` — определяет, какие данные загружать.
* Источники данных могут быть локальными (`data/data.yaml`) или использовать DVC (`use_dvc: true`).

> ***ВАЖНО!*** В качестве dvc используется gdrive, для работы с dvc необходимо положить `credentials.json` в корень проекта. Данный файл можно взять либо написав мне в tg: @nuangelova, либо скачав с [dropmefiles](https://dropmefiles.com/35AXN), пароль: re6tlu

#### Предобработка данных

```bash
python -m parkinsons_desease_progression_prediction.commands task=preprocess_data task.mode=train
```

* `mode=train|inference` — выбор режима обработки.
* Все параметры и фичи задаются в `data/data.yaml`.

### Валидация

Во время обучения данные автоматически разделяются на тренировочную, валидационную и тестовую выборки по пациентам, чтобы избежать утечки информации:

* `test_size`: пропорция тестовой выборки
* `val_size`: пропорция валидации

Они настраиваются в `task/*.yaml`.

## Inference

После обучения модели вы можете использовать её для генерации предсказаний на новых данных.  
Процедура инференса запускается отдельно и использует минимальный набор зависимостей благодаря формату ONNX.

### Запуск инференса

Для запуска ансамбля моделей (LightGBM + NN) используйте следующую команду:

```bash
python -m parkinsons_desease_progression_prediction.commands task=infer
```

### Что происходит при инференсе

* Загружаются обученные ONNX-модели (`LightGBM` и `NN`)
* Выполняется предобработка тестовых данных (если `use_preprocessing: True`)
* Выполняются предсказания обеих моделей
* Предсказания агрегируются (среднее или взвешенное среднее)
* Генерируется `submission`-файл с предсказаниями

---

### Пример входных данных

По умолчанию данные подгружаются **из DVC** в виде следующих файлов (настраивается в `data/data.yaml`):

#### `test.csv`— данные на уровне пептидов

| Столбец         | Описание                                                                 |
|------------------|--------------------------------------------------------------------------|
| `visit_id`       | Уникальный ID визита пациента                                            |
| `visit_month`    | Месяц визита относительно первого визита                                 |
| `patient_id`     | Уникальный ID пациента                                                   |
| `UniProt`        | UniProt ID белка, которому принадлежит данный пептид                     |
| `Peptide`        | Последовательность аминокислот (уникальный идентификатор пептида)        |
| `PeptideAbundance` | Частота встречаемости данного пептида в образце (абсолютная величина) |
| `group_key`      | Дополнительный столбец для группировки (например, по `visit_month`)      |

Пример:

| visit\_id | visit\_month | patient\_id | UniProt | NPX     | group\_key |
| --------- | ------------ | ----------- | ------- | ------- | ---------- |
| 50423\_0  | 0            | 50423       | O00391  | 33127.9 | 0          |
---

### `test_proteins.csv` — агрегированные данные по белкам

| Столбец     | Описание                                                                 |
|-------------|--------------------------------------------------------------------------|
| `visit_id`  | Уникальный ID визита пациента                                            |
| `visit_month` | Месяц визита относительно первого визита                               |
| `patient_id`| Уникальный ID пациента                                                   |
| `UniProt`   | UniProt ID белка                                                         |
| `NPX`       | Нормализованная экспрессия белка (объединённое значение по всем пептидам) |
| `group_key` | Дополнительный признак группировки (например, месяц визита)              |

Та же структура, но содержит агрегированные белковые данные. Используется в зависимости от того, какие признаки заданы в `data.yaml`.

---

### Пример выходного файла (`submission`)

| prediction\_id                      | rating | group\_key |
| ----------------------------------- | ------ | ---------- |
| 50423\_0\_updrs\_1\_plus\_6\_months | 2      | 0          |
| 50423\_0\_updrs\_3\_plus\_0\_months | 1      | 0          |

Где `prediction_id` формируется как:
`{patient_id}_{visit_month}_updrs_{part}_plus_{horizon}_months`

### Настройки инференса

Инференс настраивается через `configs/task/infer.yaml`. Вот ключевые параметры:

```yaml
use_preprocessing: True  # Включает автозапуск предобработки

ensemble_method: "average"  # или "weighted"
lgbm_weight: 0.5
nn_weight: 0.5

lgbm_onnx_path: "onnx_models/parkinsons_lgbm_model.onnx"
nn_onnx_path: "onnx_models/parkinsons_nn_model.onnx"

output_path: "predictions"
save_individual_predictions: true
```

Вы можете переопределять параметры прямо из командной строки:

```bash
python -m parkinsons_desease_progression_prediction.commands task=infer task.ensemble_method=weighted task.lgbm_weight=0.7 task.nn_weight=0.3
```
